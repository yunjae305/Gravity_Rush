# 운빨 서바이버 프로토타입 설계

## 목표

기존 `Gravity Gem Rush`의 단일 캔버스 프로토타입을 `뱀파이어 서바이벌`식 생존 이동과 `운빨존망겜`식 확률 뽑기 및 자동 합성 루프를 결합한 브라우저 게임으로 재구성한다. 이번 단계의 핵심은 화려한 연출보다 `코인 수급 -> 소환 -> 자동 합성 -> 전투력 급상승`의 재미를 검증하는 것이다.

## 현재 프로젝트 기준

- 프로젝트는 Next.js App Router 기반의 단일 페이지 구조다.
- 핵심 게임 로직은 현재 `app/page.tsx` 한 파일에 모여 있다.
- 렌더링은 `canvas` 중심이며, 상단과 하단에 React UI를 함께 배치하는 구조다.
- 현재는 중력 반전 러너 규칙으로 작성되어 있어 플레이어 이동, 적 생성, 공격, 경제 구조를 전면 교체해야 한다.

## 핵심 플레이 루프

1. 플레이어는 필드 안을 자유롭게 이동하며 적을 피한다.
2. 플레이어 주변의 무기들이 자동으로 적을 공격한다.
3. 적을 처치하면 코인이 드랍된다.
4. 코인이 일정량 모이면 플레이어가 직접 소환 입력을 눌러 무작위 무기를 획득한다.
5. 같은 종류와 같은 등급의 무기가 2개 모이면 즉시 자동 합성된다.
6. 합성이나 초희귀 직출로 전투력이 급증하며 더 오래 생존할 수 있다.

## 시스템 설계

### 플레이어와 생존

- 플레이어는 캔버스 내부를 `WASD`와 방향키로 이동한다.
- 적과 직접 충돌하면 체력이 감소한다.
- 체력이 0이 되면 게임 오버가 된다.
- 게임 시작 전과 게임 오버 상태에서는 간단한 오버레이 문구와 재시작 입력을 제공한다.

### 적 웨이브

- 적은 화면 바깥에서 생성되어 플레이어를 추적한다.
- 시간이 지날수록 생성 간격, 이동 속도, 체력 중 최소 한 가지 이상이 증가한다.
- 프로토타입 단계에서는 1종류 또는 2종류 적만 사용해도 충분하다.

### 자동 공격 무기

- 플레이어는 직접 공격하지 않는다.
- 무기는 플레이어 주위를 회전하거나 일정 주기로 가까운 적에게 투사체를 발사한다.
- 프로토타입에서는 무기 종류를 3개로 제한한다.
- 예시 무기:
  - `Orb`: 플레이어 주위를 돌며 접촉 피해를 준다.
  - `Bolt`: 가장 가까운 적에게 직선 투사체를 발사한다.
  - `Saw`: 짧은 범위에서 빠르게 회전하며 다단 히트를 준다.

### 가챠 등급

- 등급은 `일반`, `희귀`, `영웅`, `전설`, `신화` 5단계로 둔다.
- 별도로 매우 낮은 확률의 `조커`를 둔다.
- 기본 소환은 코인을 소비해 1회 실행한다.
- 초기 프로토타입 확률 예시:
  - `조커` 0.4%
  - `신화` 0.2%
  - `전설` 4.4%
  - `영웅` 15%
  - `희귀` 30%
  - `일반` 50%

### 자동 합성

- 같은 종류, 같은 등급의 무기가 2개 모이면 즉시 상위 등급 1개로 합쳐진다.
- `전설` 2개가 합쳐지면 `신화` 1개가 된다.
- `신화`는 더 이상 합성되지 않는다.
- `조커`는 같은 등급의 아무 무기와도 합성 재료가 될 수 있다.
- 합성은 한 번 발생한 뒤에도 연쇄적으로 다시 검사해 연속 승급을 허용한다.

### 경제와 밸런스

- 적 처치 시 코인을 드랍한다.
- 코인은 자동 획득 또는 근접 획득 중 하나로 구현한다.
- 프로토타입에서는 템포를 위해 자동 흡수보다 `근처에 가면 빨려오는 방식`이 적절하다.
- 기본 소환 비용은 고정값으로 시작하고, 첫 버전에서는 가격 상승 시스템을 넣지 않는다.

### UI

- 상단: 체력, 생존 시간, 코인, 처치 수
- 우측 또는 하단 패널: 현재 보유 무기 목록, 등급, 최근 합성 로그
- 중앙: 캔버스 전장
- 시작/오버레이: 조작법과 소환 키 안내

## 구현 구조

현재 코드베이스 규모를 고려해 첫 구현은 지나친 파일 분리보다 `app/page.tsx` 중심을 유지하되, 순수 로직 헬퍼를 분리하는 방식이 적합하다.

- `app/page.tsx`
  - React UI
  - 입력 연결
  - 캔버스 루프
  - 게임 상태 동기화
- `app/gameData.ts`
  - 무기 종류 정의
  - 등급 정보
  - 가챠 확률 테이블
  - 소환 비용과 기본 수치
- `app/gameLogic.ts`
  - 가중치 뽑기
  - 무기 생성
  - 자동 합성
  - 조커 처리
  - 순수 계산 유틸

## 데이터 모델

- `GameState`
  - `ready | playing | gameover`
- `Player`
  - 위치, 이동 속도, 체력, 최대 체력
- `Enemy`
  - 위치, 체력, 속도, 크기, 보상 코인
- `Coin`
  - 위치, 값, 흡수 상태
- `WeaponInstance`
  - 고유 id, 종류, 등급, 조커 여부, 공격 주기, 피해량
- `Projectile`
  - 위치, 속도, 대상 또는 방향, 피해량
- `MergeLog`
  - 시간, 재료 정보, 결과 정보

## 입력 설계

- 이동: `WASD`, 방향키
- 소환: `Space`
- 시작/재시작: `Enter` 또는 클릭

`Space`는 전투 중 코인 소모 소환으로 사용하고, 시작 전에는 시작 입력으로도 겸용한다.

## 연출 방향

- 캔버스 배경은 현재 프로젝트의 네온 톤을 유지한다.
- 코인 흡수, 소환 성공, 합성 발생, 신화 획득 때 파티클을 강화한다.
- 최근 뽑기 결과와 합성 결과를 텍스트 로그로 짧게 보여준다.
- 첫 버전은 사운드 없이도 상태 변화를 명확히 느끼게 하는 시각 정보에 집중한다.

## 실패 처리와 제약

- 코인이 부족하면 소환은 무시하고 짧은 피드백만 준다.
- 무기 수가 많아져도 캔버스 성능이 급격히 떨어지지 않도록 투사체 수와 적 수의 상한을 둔다.
- 외부 라이브러리는 추가하지 않고 현재 Next.js + React + TypeScript 범위 안에서 구현한다.

## 테스트와 검증

- `gameLogic.ts`의 확률 뽑기와 자동 합성은 분리된 순수 함수로 만들어 테스트 가능하게 한다.
- 최소 검증 항목:
  - 동일 종류 동일 등급 2개가 상위 등급 1개로 합쳐지는지
  - 조커가 같은 등급 무기와 합성되는지
  - `신화`는 추가 승급되지 않는지
  - 소환 결과가 정의된 등급 집합만 반환하는지
- 앱 전체는 `npm.cmd run build`로 타입과 프로덕션 빌드를 검증한다.
